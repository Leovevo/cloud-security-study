## 🏠 1. 호스팅 (Hosting) : "지정된 원룸이나 단독주택 월세 계약"
전통적인 호스팅은 데이터센터에 있는 특정한 '물리적 서버 기기(하드웨어)'의 전체나 일부를 고정적으로 빌려 쓰는 방식입니다.

- 공용 호스팅(Shared): 커다란 서버 한 대를 여러 명이 방을 쪼개어 나눠 쓰는 원룸과 같습니다.

- 단독 호스팅(Dedicated): 서버 기기 한 대를 통째로 나 혼자 쓰는 단독주택과 같습니다.

 - 핵심 특징: 물리적인 기기 하나에 종속되어 있기 때문에, 내가 빌린 공간만큼만 쓸 수 있고 매달 트래픽이 있든 없든 정해진 월세(고정비)를 냅니다.

## ☁️ 2. 클라우드 (Cloud) : "필요한 만큼 늘리고 줄이는 마법의 비즈니스 호텔"
클라우드는 수많은 물리적 서버들을 거대한 네트워크로 묶어놓고, 그 안에서 필요한 만큼의 컴퓨팅 자원(CPU, 메모리 등)을 소프트웨어적으로 가상화하여 떼어내어 사용하는 방식입니다. (AWS, Google Cloud 등이 대표적입니다.)

- 핵심 특징: 특정한 기계 한 대에 얽매이지 않습니다. 접속자가 갑자기 10,000명 몰리면 1초 만에 서버 10,000대를 복제해서 대응하고, 손님이 빠지면 다시 1대로 줄인 뒤 딱 사용한 만큼만 요금을 지불(종량제)합니다.

## ⚖️ 3. 각각의 장단점 요약

- 호스팅의 장단점

>- 장점: 비용 예측이 쉽고 고정되어 있습니다. 복잡한 가상 네트워크 인프라 지식이 없어도 초기 세팅이 직관적이어서 소규모 개인 블로그나 트래픽 변화가 없는 사내 시스템에 적합합니다.
- 단점: 트래픽 폭주(예: 수강신청, 특가 이벤트)가 발생하면 물리적 한계에 부딪혀 서버가 다운됩니다.

- 클라우드의 장단점

>- 장점: 유연성과 안정성이 압도적입니다. 트래픽 폭주에 실시간으로 대응하며, 전 세계 어디서든 똑같은 인프라를 순식간에 배포할 수 있어 대규모 퍼블릭 서비스에 필수적입니다.
- 단점: 방심하고 불필요한 자원을 켜두거나 아키텍처 설계를 잘못하면 엄청난 '요금 폭탄'을 맞을 수 있습니다. 또한, 인프라를 안전하게 다루기 위한 전문적인 엔지니어링 지식이 깊게 요구됩니다.

# Git 과 Github는 무엇인가

## 💾 1. Git (깃) : "내 컴퓨터 안의 코드 타임머신"
Git은 로컬 환경(내 컴퓨터)에서 작동하는 '버전 관리 시스템(VCS, Version Control System)'입니다.

- 핵심 역할: 코드를 작성하다가 특정 시점마다 '사진(Commit)'을 찍어두고, 언제든지 과거의 특정 시점으로 코드를 되돌리거나 변경된 이력을 추적할 수 있게 해줍니다. 게임의 '세이브 포인트'나 컴퓨터의 '타임머신'과 같은 역할입니다.

- 작동 위치: 오프라인 상태라도 내 컴퓨터 안에서 완벽하게 작동합니다.

- 장점: 원본 코드를 망치지 않고, 여러 갈래(Branch)로 안전하게 복사본을 만들어 새로운 기능을 테스트해 볼 수 있습니다.

## 🌐 2. GitHub (깃허브) : "개발자들의 구글 드라이브이자 소셜 네트워크"
GitHub는 내 컴퓨터에서 Git으로 관리하고 있는 코드(버전 기록 포함)를 인터넷상에 올려두고 다른 사람들과 공유할 수 있게 해주는 '클라우드 원격 저장소 서비스'입니다.

- 핵심 역할: 내 컴퓨터가 고장 나도 코드가 날아가지 않게 백업해 주는 클라우드 역할을 하며, 전 세계의 수많은 개발자가 한 프로젝트에 모여 동시에 코드를 수정하고 협업할 수 있는 환경을 제공합니다.

- 작동 위치: 인터넷이 연결된 온라인 클라우드 환경에서 작동합니다.

- 장점: 코드를 단순히 저장하는 것을 넘어, 다른 사람의 코드를 리뷰하고, 버그를 신고하고, 오픈 소스 프로젝트에 기여할 수 있는 강력한 협업 커뮤니티 기능을 제공합니다.

## 💾 3. 가장 쉬운 비유: 게임의 '세이브 포인트'

Git에서 commit(커밋)은 한마디로 "파일들의 현재 상태를 사진으로 찰칵 찍어서 영구적인 기록으로 남기는 것"입니다.

- 코드를 작성하다가 "아, 이 정도면 하나의 의미 있는 작업이 끝났다" 싶을 때 커밋을 하면, 그 순간의 모든 파일 상태가 마치 박제되듯 내 컴퓨터에 안전하게 저장됩니다.

- 안전한 복구 (타임머신): 나중에 코드를 잘못 수정해서 사이트가 완전히 망가지더라도, 이전에 커밋해 둔(저장해 둔) 과거 시점으로 언제든지 100% 완벽하게 되돌릴 수 있습니다.

- 작업 이력 추적: 방금 작성하셨던 git commit -m "docs: Git 에러 트러블슈팅..." 명령어에서 -m은 Message(메시지)의 약자입니다. 사진 뒷면에 "이날은 에러를 해결했음"이라고 포스트잇을 붙여두는 것과 같습니다. 나중에 이 메모들만 쭉 모아보면, 이 웹사이트가 어떤 과정을 거쳐 만들어졌는지 역사책처럼 한눈에 파악할 수 있습니다.
