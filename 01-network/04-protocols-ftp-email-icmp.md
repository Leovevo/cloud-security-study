## 1. 프로토콜(Protocol)이란?

프로토콜은 컴퓨터나 네트워크 장비가 서로 통신하기 위해 정해놓은 **규칙과 약속**이다.

사람들이 대화할 때 사용하는 언어와 대화 순서가 있는 것처럼, 컴퓨터도 데이터를 주고받기 위해 정해진 통신 규칙을 사용한다.

예를 들어 파일을 전송할 때는 FTP, 이메일을 전송할 때는 SMTP, 네트워크 오류를 알릴 때는 ICMP를 사용할 수 있다.

| 프로토콜 | 주요 역할 | OSI 계층 | 하위 프로토콜 |
|---|---|---|---|
| FTP | 파일 전송 | 7계층 응용 | TCP |
| SMTP | 이메일 전송 | 7계층 응용 | TCP |
| POP3 | 이메일 가져오기 | 7계층 응용 | TCP |
| IMAP | 서버의 이메일 조회·관리 | 7계층 응용 | TCP |
| ICMP | 네트워크 제어·오류 알림 | 3계층 네트워크 | IP |

이번 과제에서는 FTP, 이메일 프로토콜, ICMP를 중심으로 각각의 동작 원리와 차이점을 알아보겠다.

# 2. FTP(File Transfer Protocol)

## 2-1. FTP란?

FTP는 네트워크를 통해 클라이언트와 서버 사이에서 파일을 전송하는 응용 계층 프로토콜이다.

쉽게 비유하면 FTP는 **창고 관리자에게 파일을 요청하거나 창고에 파일을 맡기는 서비스**와 비슷하다.

사용자는 FTP 서버에 접속해 파일을 업로드하거나 다운로드할 수 있으며, 서버에서 허용한 범위 안에서 파일 목록 조회나 디렉터리 작업도 수행할 수 있다.

FTP의 가장 중요한 특징은 **제어 채널(Control Channel)과 데이터 채널(Data Channel)을 분리한다는 점**이다.

## 2-2. 제어 채널과 데이터 채널

FTP는 명령을 전달하는 연결과 실제 데이터를 전달하는 연결을 구분한다.

### 제어 채널(Control Channel)

제어 채널은 클라이언트가 FTP 서버에 명령을 보내고 서버의 응답을 받기 위한 연결이다.

일반적으로 서버의 **TCP 21번 포트**를 사용한다.

대표적인 FTP 명령은 다음과 같다.

| 명령어 | 의미 |
|---|---|
| USER | 사용자 이름 전달 |
| PASS | 비밀번호 전달 |
| LIST | 디렉터리 목록 요청 |
| RETR | 서버의 파일 다운로드 요청 |
| STOR | 서버에 파일 업로드 요청 |
| QUIT | FTP 세션 종료 |

예를 들어 클라이언트가 `RETR report.pdf`를 전송하면 서버에 해당 파일의 다운로드를 요청하는 것이다.

### 데이터 채널(Data Channel)

데이터 채널은 실제 파일 내용이나 디렉터리 목록을 전달하는 별도의 TCP 연결이다.

데이터 채널이 연결되는 방식은 FTP의 Active Mode와 Passive Mode에 따라 달라진다.

```text
             FTP Client
                 |
       ┌─────────┴─────────┐
       |                   |
   제어 채널           데이터 채널
  명령과 응답        파일 및 목록 전송
       |                   |
       └─────────┬─────────┘
                 |
              FTP Server
```

즉, **제어 채널은 무엇을 할지 지시하는 통로이고, 데이터 채널은 실제 파일을 주고받는 통로**라고 이해하면 된다.

## 2-3. Active Mode(능동 모드)

Active Mode에서는 클라이언트가 제어 채널을 연결한 뒤, 데이터 연결에 사용할 자신의 주소와 포트를 서버에 알려준다.

그다음 서버가 클라이언트 쪽으로 데이터 연결을 시작한다.

```text
FTP Client                 FTP Server
    |                           |
    |---- 제어 연결 ----------->| TCP 21
    |---- PORT 명령 ----------->|
    |                           |
    |<--- 데이터 연결 ----------| TCP 20(일반적인 경우)
    |                           |
    |<==== 파일 다운로드 ========|
```

### 특징

- 제어 연결은 클라이언트가 시작한다.
- 데이터 연결은 서버가 시작한다.
- 전통적인 Active FTP에서 서버 데이터 연결의 출발지 포트는 보통 TCP 20이다.
- 클라이언트가 방화벽이나 NAT 뒤에 있으면 외부에서 들어오는 데이터 연결이 차단될 수 있다.

쉽게 말하면 사용자가 창고에 전화해서 물건을 요청한 다음, **창고 측에서 사용자의 집으로 배송을 시작하는 방식**이다.

## 2-4. Passive Mode(수동 모드)

Passive Mode에서는 클라이언트가 서버에 데이터 연결을 위한 포트를 요청한다.

서버는 자신이 대기하고 있는 IP 주소와 포트 정보를 알려주며, 클라이언트가 해당 포트로 연결한다.

```text
FTP Client                 FTP Server
    |                           |
    |---- 제어 연결 ----------->| TCP 21
    |---- PASV 명령 ----------->|
    |<--- 서버 데이터 포트 안내--|
    |                           |
    |---- 데이터 연결 --------->| 지정된 포트
    |                           |
    |<==== 파일 다운로드 ========|
```

### 특징

- 제어 연결과 데이터 연결을 모두 클라이언트가 시작한다.
- 서버는 별도로 지정한 데이터 포트에서 연결을 기다린다.
- 일반적으로 클라이언트가 NAT나 방화벽 뒤에 있는 환경에서 사용하기 편리하다.
- 서버 측에서는 데이터 연결을 위한 포트 범위와 방화벽 설정이 필요할 수 있다.

이는 사용자가 창고에 전화한 뒤, **창고에서 안내한 수령 장소로 직접 찾아가는 방식**과 비슷하다.

단, Active와 Passive의 차이는 **데이터 연결을 누가 시작하는지**에 관한 것이다. 실제 파일은 두 모드 모두 업로드하거나 다운로드할 수 있다.

또한 IPv6 등의 환경에서는 기존 `PORT`, `PASV` 명령을 확장한 `EPRT`, `EPSV` 명령을 사용할 수 있다.

## 2-5. Active Mode와 Passive Mode 비교

| 구분 | Active Mode | Passive Mode |
|---|---|---|
| 제어 연결 시작 | 클라이언트 | 클라이언트 |
| 데이터 연결 시작 | 서버 | 클라이언트 |
| 서버 제어 포트 | TCP 21 | TCP 21 |
| 서버 데이터 포트 | 보통 TCP 20에서 시작 | 서버가 지정한 포트 |
| 클라이언트 방화벽 | 인바운드 연결 문제가 발생할 수 있음 | 상대적으로 유리 |
| 서버 방화벽 | 데이터 연결을 위한 아웃바운드 허용 필요 | 지정 데이터 포트의 인바운드 허용 필요 |

### FTP의 보안 문제

기본 FTP는 인증 정보와 파일 내용을 암호화하지 않는다.

따라서 네트워크에서 전송 내용을 가로채면 사용자 이름, 비밀번호, 파일 내용 등이 노출될 위험이 있다.

이를 해결하기 위한 대표적인 대안은 다음과 같다.

- **FTPS:** FTP 통신에 TLS 암호화를 적용한 방식
- **SFTP:** SSH를 기반으로 파일을 전송하는 별도의 프로토콜

SFTP와 FTPS는 이름이 비슷하지만 서로 다른 프로토콜이다.

또한 Passive Mode 자체가 FTP 통신을 암호화하거나 더 안전하게 만드는 것은 아니다.

# 3. 이메일 프로토콜 — SMTP, POP3, IMAP

이메일에는 메시지를 보내는 과정과 받은 메시지를 확인하는 과정이 존재한다.

각 과정에서 사용하는 프로토콜이 다르다.

쉽게 생각하면 다음과 같다.

- SMTP: 편지를 보내는 우체국
- POP3: 우체국의 편지를 집으로 가져오기
- IMAP: 우체국에 편지를 보관하면서 여러 장소에서 확인하기

## 3-1. SMTP(Simple Mail Transfer Protocol)

SMTP는 이메일을 전송하거나 메일 서버 사이에서 메시지를 중계하는 응용 계층 프로토콜이다.

사용자가 이메일의 보내기 버튼을 누르면 메일 클라이언트는 SMTP 기반의 메시지 제출 서비스를 통해 발송 요청을 전달할 수 있다.

이후 발신 측 메일 서버가 수신 측 메일 서버에 이메일을 전송한다.

```text
발신자
   |
   | SMTP - 메시지 제출
   v
발신 메일 서버
   |
   | SMTP - 서버 간 전송
   v
수신 메일 서버
   |
   | 메일함에 저장
   v
수신자
```

SMTP에서 주로 사용되는 포트는 다음과 같다.

| TCP 포트 | 일반적인 용도 |
|---|---|
| 25 | 메일 서버 간 SMTP 전송·중계 |
| 587 | 클라이언트의 메일 제출, 일반적으로 STARTTLS 사용 |
| 465 | 처음부터 TLS 연결을 사용하는 메일 제출 |

SMTP의 핵심 역할은 이메일을 **보내고 전달하는 것**이다.

수신자의 메일함에 저장된 메시지를 읽고 관리하는 작업은 주로 POP3나 IMAP으로 처리한다.

## 3-2. POP3(Post Office Protocol Version 3)

POP3는 메일 서버에 저장된 이메일을 클라이언트로 가져오는 프로토콜이다.

쉽게 말하면 우체국에 도착한 편지를 집으로 가져와 보관하는 방식이다.

POP3는 일반적으로 메일을 다운로드하는 데 중점을 둔다.

```text
메일 서버
    |
    | POP3 다운로드
    v
사용자 PC
    |
    └─ 로컬에 이메일 보관
```

POP3는 메일을 다운로드한 후 서버에서 삭제하는 방식으로 운용할 수 있지만, 클라이언트 설정에 따라 서버에 메일을 남겨둘 수도 있다.

### 특징

- 구현과 사용 방식이 비교적 단순하다.
- 메일을 로컬 기기에 저장해 오프라인으로 읽을 수 있다.
- 서버의 편지함이나 읽음 상태를 여러 기기와 동기화하는 기능이 제한적이다.
- 메일 보관 정책에 따라 서버 저장 공간을 줄일 수 있다.

기본 포트는 TCP 110이며, TLS를 즉시 사용하는 POP3S의 기본 포트는 TCP 995이다.

## 3-3. IMAP(Internet Message Access Protocol)

IMAP은 메일 서버에 저장된 이메일을 조회하고 관리하는 프로토콜이다.

POP3와 달리 서버의 메일함을 중심으로 메시지와 폴더 상태를 관리한다.

쉽게 생각하면 편지를 우체국에 보관한 상태에서 PC와 스마트폰으로 확인하는 방식이다.

```text
               메일 서버
                 |
          ┌──────┴──────┐
          |             |
       스마트폰          PC
          |             |
          └── 동기화 ────┘
```

예를 들어 스마트폰에서 이메일을 읽음으로 표시하면 해당 정보가 서버에 반영되고, PC에서도 동기화된 읽음 상태를 확인할 수 있다.

### 특징

- 서버 중심의 이메일 관리
- 여러 기기의 메일함 상태 동기화
- 읽음·안 읽음 등의 상태 관리
- 폴더 관리 및 서버 측 검색 기능
- 필요한 메시지나 일부 내용만 선택적으로 가져올 수 있음

기본 포트는 TCP 143이며, TLS를 즉시 사용하는 IMAPS의 기본 포트는 TCP 993이다.

## 3-4. SMTP, POP3, IMAP 비교

| 구분 | SMTP | POP3 | IMAP |
|---|---|---|---|
| 주된 목적 | 메일 전송 | 메일 가져오기 | 메일 조회 및 동기화 |
| 방향 | 발신·서버 간 중계 | 서버 → 클라이언트 | 서버 ↔ 클라이언트 |
| 서버 중심 관리 | 전송 작업 중심 | 제한적 | 강력함 |
| 여러 기기 동기화 | 해당 없음 | 제한적 | 지원 |
| 대표 포트 | 25, 587, 465 | 110, 995 | 143, 993 |

핵심적으로 SMTP는 **보내기**, POP3는 **가져오기**, IMAP은 **서버에 보관하면서 관리하기**라고 구분할 수 있다.

# 4. POP3와 IMAP의 보안 및 운영·관리 측면 비교

이번 과제에서 특히 중요하게 다루어야 할 부분이다.

POP3와 IMAP은 둘 다 이메일을 확인하는 프로토콜이지만 데이터 보관 위치와 동기화 방식에 따라 운영상 차이가 발생한다.

## 4-1. 보안 측면

### POP3의 보안 특성

POP3로 메시지를 내려받고 서버에서 삭제하도록 구성했다면 서버에 남는 메시지의 양을 줄일 수 있다.

하지만 해당 PC가 분실되거나 악성코드에 감염되면 로컬에 보관된 이메일이 유출될 위험이 있다.

또한 기기가 고장 났을 때 별도의 백업이 없다면 이메일을 복구하기 어려울 수 있다.

### IMAP의 보안 특성

IMAP은 서버를 중심으로 메일을 관리하므로 여러 기기에서 접근하고 데이터를 복구하기 편리하다.

반면 계정이 탈취되면 공격자가 서버에 보관된 많은 이메일에 접근할 수 있다.

따라서 계정 인증, 접근 권한, 서버 보안, 백업 및 보관 정책이 중요하다.

### 공통적인 보안 대책

POP3와 IMAP 모두 TLS를 이용하여 네트워크 통신을 암호화할 수 있다.

또한 서비스에서 지원하는 경우 다중 인증(MFA), OAuth 기반 인증, 접근 기록 점검 등의 보호 조치를 적용할 수 있다.

**POP3 자체가 IMAP보다 안전하거나, IMAP 자체가 POP3보다 안전하다고 단정할 수는 없다.**

보안 수준은 실제 암호화 설정과 인증 방식, 서버·단말기 관리에 따라 달라진다.

## 4-2. 운영·관리 측면

| 항목 | POP3 | IMAP |
|---|---|---|
| 메일 저장 | 주로 로컬에 다운로드 | 서버 중심 |
| 여러 기기 사용 | 동기화 기능 제한적 | 동기화에 유리 |
| 서버 저장 공간 | 서버 삭제 정책 시 절약 가능 | 서버에 장기 보관하는 경우 증가 |
| 백업 관리 | 로컬 백업 중요 | 서버 백업·보관 정책 중요 |
| 폴더 관리 | 기본 프로토콜 기능 제한 | 서버 측 폴더 관리 지원 |
| 오프라인 활용 | 다운로드한 메일 사용 가능 | 캐시한 메일 사용 가능 |
| 장애 및 복구 | 로컬 기기 상태가 중요 | 서버의 상태와 백업이 중요 |

### 어떤 방식을 선택해야 할까?

개인용 PC 한 대에서 이메일을 내려받아 보관하는 환경이라면 POP3가 적합할 수 있다.

반면 스마트폰, 노트북, PC 등 여러 기기에서 같은 이메일을 확인하거나 회사 차원에서 메일함을 중앙 관리해야 한다면 IMAP이 일반적으로 더 편리하다.

조직에서는 메일 보존 기간, 개인정보 보호, 백업, 감사 및 접근 통제 정책도 함께 고려해야 한다.

# 5. ICMP(Internet Control Message Protocol)

## 5-1. ICMP란?

ICMP는 IP 네트워크에서 오류 및 제어 정보를 전달하는 프로토콜이다.

네트워크 계층에서 동작하며, IPv4의 ICMP는 TCP나 UDP 포트를 이용하지 않고 IP 패킷 안에 직접 실려 전달된다.

ICMP의 주된 목적은 파일이나 이메일 같은 사용자 데이터를 전송하는 것이 아니라, **네트워크 통신 상태와 문제에 관한 정보를 전달하는 것**이다.

쉽게 비유하면 도로의 교통 안내 시스템과 비슷하다.

목적지까지 가는 길에 문제가 발생했거나 다른 경로가 적절할 때 관련 정보를 알려주는 것이다.

대표적인 활용 예시로 `ping`과 `traceroute` 또는 Windows의 `tracert`가 있다.

- `ping`: ICMP Echo Request와 Echo Reply를 이용해 응답을 확인
- `traceroute`: TTL 또는 Hop Limit을 조절해 경유 장비를 확인

단, ICMP 응답이 오지 않는다고 해서 상대 장비가 반드시 꺼져 있는 것은 아니다. 방화벽 정책이나 응답 제한 때문에 메시지가 도착하지 않을 수도 있다.

## 5-2. ICMP 메시지 구조

ICMPv4 메시지에는 일반적으로 다음 정보가 포함된다.

| 필드 | 설명 |
|---|---|
| Type | 메시지의 종류 |
| Code | 해당 메시지의 세부적인 의미 |
| Checksum | ICMP 메시지 오류 검사 |
| 기타 데이터 | 메시지 종류에 따른 추가 정보 |

예를 들어 `Type 3, Code 3`이라면 IPv4 ICMP의 Destination Unreachable 중 Port Unreachable을 의미한다.

이번 과제에서는 세 가지 오류 및 제어 메시지를 중심으로 살펴보겠다.

# 6. ICMP Time Exceeded

Time Exceeded는 패킷이 정해진 수명 제한을 초과했거나, IPv4 단편화 패킷 재조립 시간을 초과했을 때 사용되는 메시지다.

IPv4에서 **Type 11**을 사용한다.

## 6-1. TTL(Time To Live)이란?

TTL은 IP 패킷이 네트워크에서 무한히 순환하지 않도록 제한하는 값이다.

라우터를 통과할 때마다 일반적으로 1씩 감소한다.

TTL이 0이 되면 라우터는 해당 패킷을 폐기하고 Time Exceeded 메시지를 보낼 수 있다.

```text
PC A
 TTL = 3
   |
   v
Router 1
 TTL = 2
   |
   v
Router 2
 TTL = 1
   |
   v
Router 3
 TTL = 0 → 패킷 폐기
   |
   └── ICMP Time Exceeded 알림
```

이 과정은 `traceroute`가 중간 경유지를 확인하는 데 활용할 수 있다.

TTL 값을 1, 2, 3과 같이 조절한 패킷을 보내면 중간 라우터가 반환하는 Time Exceeded 메시지를 통해 경로를 추정할 수 있다.

## 6-2. Time Exceeded 세부 코드

| Type | Code | 의미 |
|---|---|---|
| 11 | 0 | 전송 중 TTL 초과 |
| 11 | 1 | IPv4 단편 재조립 시간 초과 |

Time Exceeded는 단순히 서버 응답이 느리다는 의미가 아니라, 패킷의 수명이나 재조립 시간 제한과 관련된 메시지다.

# 7. ICMP Redirect

Redirect는 라우터가 호스트에게 **더 적절한 다음 홉이 존재한다는 사실을 알려주는 메시지**다.

IPv4에서 **Type 5**를 사용한다.

## 7-1. Redirect 동작 원리

예를 들어 PC A가 Router 1을 통해 목적지로 패킷을 보내고 있다고 가정하자.

하지만 실제 목적지로 가는 더 적절한 다음 경로가 같은 네트워크에 있는 Router 2라면, Router 1이 PC A에게 Router 2를 사용하도록 안내할 수 있다.

```text
             목적지 네트워크
                ^
                |
             Router 2
              ^   ^
              |   |
      Redirect|   | 더 적절한 경로
              |   |
PC A ------ Router 1
       기존 경로
```

이처럼 Redirect는 효율적인 경로를 안내하기 위한 제어 메시지다.

## 7-2. Redirect의 세부 코드

| Type | Code | 의미 |
|---|---|---|
| 5 | 0 | 네트워크에 대한 경로 변경 |
| 5 | 1 | 호스트에 대한 경로 변경 |
| 5 | 2 | 서비스 유형과 네트워크에 대한 경로 변경 |
| 5 | 3 | 서비스 유형과 호스트에 대한 경로 변경 |

### Redirect의 보안 문제

Redirect 메시지를 신뢰할 수 없는 장비가 위조하면 잘못된 경로로 트래픽을 유도할 위험이 있다.

이는 트래픽 가로채기나 중간자 공격으로 연결될 수 있다.

따라서 일부 시스템에서는 ICMP Redirect 메시지를 제한하거나 무시하도록 설정한다.

Redirect는 OSPF나 BGP처럼 라우터들이 경로 정보를 교환하는 동적 라우팅 프로토콜과는 다르다.

# 8. ICMP Destination Unreachable

Destination Unreachable은 패킷을 목적지까지 정상적으로 전달할 수 없을 때 사용되는 오류 메시지다.

IPv4에서는 **Type 3**을 사용한다.

예를 들어 목적지 네트워크로 가는 경로가 없거나, 목적지의 UDP 포트에서 해당 서비스를 사용하지 않는 경우 등에 발생할 수 있다.

```text
PC A
  |
  | 목적지로 패킷 전송
  v
Router
  |
  X 목적지로 전달 불가능
  |
  └── ICMP Destination Unreachable
          |
          v
         PC A
```

## 8-1. Destination Unreachable 세부 코드

대표적인 IPv4 ICMP 코드는 다음과 같다.

| Type | Code | 메시지 | 의미 |
|---|---|---|---|
| 3 | 0 | Network Unreachable | 목적지 네트워크에 도달 불가 |
| 3 | 1 | Host Unreachable | 목적지 호스트에 도달 불가 |
| 3 | 2 | Protocol Unreachable | 목적지에서 해당 프로토콜을 처리할 수 없음 |
| 3 | 3 | Port Unreachable | 목적지 포트에 도달할 수 없음 |
| 3 | 4 | Fragmentation Needed | 패킷 단편화가 필요하지만 DF 설정으로 수행 불가 |

예를 들어 UDP 패킷을 전송했는데 목적지 포트에서 서비스를 제공하지 않는다면 ICMP Port Unreachable이 반환될 수 있다.

그러나 모든 오류가 반드시 ICMP 메시지로 반환되는 것은 아니다.

라우터의 정책이나 방화벽에서 ICMP 메시지가 제한될 수 있기 때문이다.

## 8-2. 세 가지 메시지의 차이점

| 구분 | Time Exceeded | Redirect | Destination Unreachable |
|---|---|---|---|
| IPv4 Type | 11 | 5 | 3 |
| 목적 | 시간·수명 제한 알림 | 더 적절한 경로 안내 | 목적지 도달 실패 알림 |
| 대표 발생 상황 | TTL이 0이 됨 | 다른 다음 홉이 더 적절함 | 경로 없음, 포트 도달 불가 등 |
| 관련 기술 | Traceroute | 호스트 경로 제어 | 네트워크 장애 진단 |

**주의:** 위 Type 번호는 IPv4의 ICMPv4 기준이다. IPv6에서는 ICMPv6를 사용하며 메시지 Type 번호와 일부 동작 방식이 다르다.

# 9. 클라우드 보안 관점에서의 활용

이번에 학습한 프로토콜은 클라우드 환경의 네트워크 관리와 보안에도 직접적으로 연결된다.

### FTP와 파일 전송 보안

클라우드 서버에서 파일을 전송해야 한다면 기본 FTP를 그대로 사용하는 것은 보안상 위험할 수 있다.

전송 중 암호화가 필요한 환경에서는 SFTP나 적절히 구성한 FTPS 등을 고려해야 한다.

FTP를 사용하는 경우 Active/Passive 모드에 따라 데이터 연결 방향이 달라지므로 방화벽과 NAT 구성을 확인해야 한다.

### 이메일 프로토콜과 계정 보안

이메일 시스템을 운영할 때는 SMTP 전송 설정뿐만 아니라 POP3·IMAP의 인증 방식과 TLS 적용 여부도 확인해야 한다.

또한 메일 보관 정책, 계정 접근 통제, 백업 및 감사 기능도 중요하다.

### ICMP와 장애 진단

클라우드 서버에 접속할 수 없을 때는 ICMP를 이용해 네트워크 경로를 조사할 수 있다.

하지만 ICMP 응답이 없다는 사실만으로 네트워크 연결이 완전히 끊어졌다고 판단하면 안 된다.

예를 들어 AWS EC2의 Security Group에서 ICMP 인바운드 트래픽을 허용하지 않으면 Ping 요청에 응답하지 않을 수 있다.

반대로 Ping에 성공했다고 해서 SSH나 HTTP 서비스까지 정상적으로 작동하는 것은 아니다.

**네트워크 연결 문제를 정확하게 분석하려면 ICMP뿐 아니라 TCP·UDP 포트, 라우팅, 방화벽, 애플리케이션 상태를 함께 확인해야 한다.**

# 10. 결론

이번 과제를 통해 응용 계층과 네트워크 계층에서 사용하는 프로토콜의 특징을 알아보았다.

FTP는 파일을 전송하기 위해 제어 채널과 데이터 채널을 분리하며, Active Mode와 Passive Mode는 데이터 연결을 시작하는 주체가 다르다는 것을 알 수 있었다.

이메일에서는 SMTP가 메시지를 전송하고, POP3와 IMAP이 서버의 이메일을 가져오거나 관리하는 역할을 담당한다. 특히 POP3와 IMAP은 데이터 저장 방식 및 동기화 기능의 차이로 인해 보안과 운영 측면에서 서로 다른 고려 사항이 존재한다.

마지막으로 ICMP는 네트워크 오류와 제어 정보를 전달하며, Time Exceeded, Redirect, Destination Unreachable 메시지는 각각 다른 네트워크 상황을 알리는 데 사용된다는 사실을 확인했다.

이러한 프로토콜의 역할을 정확히 이해한다면 앞으로 네트워크 장애를 분석하거나 클라우드 보안 환경을 구성할 때 도움이 될 것이라고 생각한다.

## 핵심 3줄 요약

1. **FTP는 제어 채널과 데이터 채널을 분리해 파일을 전송하며, Active Mode는 서버가, Passive Mode는 클라이언트가 데이터 연결을 시작한다.**
2. **SMTP는 이메일 전송을 담당하고, POP3는 메일 다운로드 중심, IMAP은 서버 중심의 메일 관리 및 다중 기기 동기화에 적합하다.**
3. **ICMP는 네트워크 오류·제어 정보를 전달하며, Time Exceeded는 수명 초과, Redirect는 경로 변경 안내, Destination Unreachable은 목적지 도달 실패를 의미한다.**
