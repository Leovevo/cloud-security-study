## 들어가며

우리가 웹사이트에 접속하거나 친구에게 메시지를 보낼 때, 데이터는 어떻게 상대방에게 전달될까?

컴퓨터에서 전송 버튼을 누르면 몇 초도 지나지 않아 상대방 화면에 메시지가 나타난다.

하지만 그 짧은 순간에도 컴퓨터 내부에서는 여러 단계의 통신 과정이 일어난다.

이러한 네트워크 통신의 구조를 이해하는 데 도움이 되는 것이 **OSI 7계층(OSI 7 Layer)**이다.

이번 글에서는 OSI 7계층의 탄생 배경과 각 계층의 역할, 데이터 전송 단위(PDU)를 정리하고, 어려운 개념은 축구공을 전달하는 비유로 쉽게 이해해보려고 한다.

마지막에는 이러한 개념들이 실제 클라우드 보안과 어떻게 연결되는지도 살펴보겠다.

---

## 1. OSI 7계층이란?

OSI는 Open Systems Interconnection의 약자로, 서로 다른 시스템 간의 통신 과정을 설명하기 위해 만들어진 표준 참조 모델이다.

과거에는 컴퓨터 제조사마다 서로 다른 통신 방식을 사용하는 경우가 많았다.

그 결과 서로 다른 제조사의 컴퓨터를 연결하고 통신시키는 데 어려움이 있었다.

이런 문제를 해결하기 위해 ISO(국제표준화기구)는 네트워크 통신 기능을 체계적으로 정리했고, 1984년 OSI 기본 참조 모델을 국제표준으로 발표했다.

OSI 7계층은 복잡한 네트워크 통신을 일곱 개의 역할로 나누어 설명한다.

쉽게 말하면 **하나의 복잡한 일을 일곱 개의 담당 부서로 나눈 것**과 비슷하다.

각 계층은 자신에게 주어진 역할을 수행하고, 다른 계층과 협력해 데이터를 전달한다.

다만 OSI는 통신을 이해하기 위한 참조 모델이며, 오늘날 실제 인터넷에서는 TCP/IP 프로토콜 구조가 주로 사용된다.

---

## 2. OSI 7계층 전체 구조

| 계층 | 이름 | 주요 역할 | 전송 단위(PDU) |
|---|---|---|---|
| 7 | 응용(Application) | 네트워크 서비스 제공 | Data |
| 6 | 표현(Presentation) | 데이터 표현·변환 | Data |
| 5 | 세션(Session) | 논리적 대화 관리 | Data |
| 4 | 전송(Transport) | 프로그램 간 데이터 전달 | Segment / Datagram |
| 3 | 네트워크(Network) | IP 주소와 경로 선택 | Packet |
| 2 | 데이터 링크(Data Link) | 같은 링크에서 데이터 전달 | Frame |
| 1 | 물리(Physical) | 물리 신호 전송 | Bit |

※ 위 표는 입문 학습을 위해 5~7계층의 PDU를 Data로 단순화한 것이다.

데이터를 전송할 때는 일반적으로 송신 측의 7계층부터 1계층까지 내려가고, 수신 측의 1계층부터 7계층까지 올라간다고 설명한다.

이제 이 과정을 이해하기 위해 하나의 상황을 가정해보자.

**PC 1에서 PC 2로 축구공 그림(⚽)을 보내려고 한다.**

여기서 축구공은 실제로 이동하는 물건이 아니라, 축구공을 표현하는 디지털 데이터다.

이 데이터가 어떤 과정을 거쳐 상대방에게 전달되는지 각 계층에서 살펴보자.

# 3. OSI 7계층을 축구공으로 이해하기

## 3-1. 7계층 — 응용 계층(Application Layer)

### "어떤 공을 보낼까?"

친구에게 축구공 그림을 보내고 싶다고 생각해보자.

우선 PC 1에서 메시지 전송 프로그램을 실행한다.

그리고 ⚽ 그림을 선택한 후 전송 버튼을 누른다.

여기서 중요한 것은 **사용자가 어떤 네트워크 서비스를 이용할 것인지 결정하고, 프로그램이 그 서비스에 맞는 통신을 시작한다는 것**이다.

응용 계층은 사용자가 네트워크 서비스를 이용할 수 있도록 통신 기능을 제공하는 계층이다.

예를 들어 웹사이트에 접속할 때는 HTTP, 도메인 이름을 IP 주소로 알아낼 때는 DNS, 이메일을 보낼 때는 SMTP 등을 사용한다.

대표적인 프로토콜은 다음과 같다.

- HTTP / HTTPS: 웹 통신
- DNS: 도메인 이름 해석
- SMTP: 이메일 전송
- SSH: 안전한 원격 접속

**쉽게 정리하면:** 응용 계층은 "무엇을 보내고 어떤 네트워크 서비스를 이용할 것인가?"를 다루는 계층이다.

- 전송 단위(PDU): Data
- 보안 관련 사례: SQL Injection, 악성 HTTP 요청

참고로 응용 계층은 브라우저 프로그램 자체를 뜻하기보다는, 브라우저 등이 사용하는 네트워크 통신 서비스와 규약을 의미한다.

## 3-2. 6계층 — 표현 계층(Presentation Layer)

### "친구가 알아볼 수 있는 형태로 공을 준비하자!"

이번에는 PC 1에서 선택한 ⚽ 그림을 PC 2가 이해할 수 있어야 한다.

예를 들어 내가 한국어로 쓴 편지를 영어만 읽을 수 있는 친구에게 보낸다고 생각해보자.

친구가 편지를 이해하려면 서로 약속한 표현 방식이나 번역이 필요하다.

컴퓨터도 마찬가지다.

서로 다른 컴퓨터가 데이터를 올바르게 이해하려면 데이터 형식과 표현 방법이 맞아야 한다.

표현 계층에서는 데이터 형식 변환, 문자 인코딩, 압축, 암호화 등의 기능을 설명한다.

대표적인 예시는 다음과 같다.

- 문자 인코딩: UTF-8
- 데이터 형식: JPEG, PNG 등
- 압축: 데이터 크기를 줄이는 처리
- 암호화: 데이터를 허가받지 않은 사람이 쉽게 읽지 못하도록 보호

축구공 그림을 전송한다면 PC 2가 이를 정상적인 이미지나 문자로 해석할 수 있는 형식이 필요하다.

**쉽게 정리하면:** 표현 계층은 "보내는 쪽과 받는 쪽이 데이터를 같은 의미로 이해하도록 하자!"라는 역할이다.

- 전송 단위(PDU): Data
- 보안 관련 사례: 데이터 암호화와 인코딩 설정 문제

참고로 TLS 암호화는 교육용 설명에서 표현 계층과 연결하기도 하지만, 실제 TCP/IP 구현에서 독립된 6계층에 정확히 대응하는 것은 아니다.

## 3-3. 5계층 — 세션 계층(Session Layer)

### "친구와 공을 주고받는 대화를 관리하자!"

이번에는 친구와 전화 통화를 한다고 생각해보자.

전화 통화에는 일반적으로 다음과 같은 과정이 있다.

1. 통화를 시작한다.
2. 대화를 이어간다.
3. 통화를 종료한다.

통신에서도 시스템 사이의 논리적인 대화를 관리할 필요가 있다.

이러한 대화 관계를 **세션(Session)**이라고 한다.

OSI 모델의 세션 계층은 통신의 설정, 유지, 종료, 동기화 같은 기능을 설명한다.

축구공 비유에서는 PC 1과 PC 2가 공 그림을 주고받는 대화의 흐름을 관리하는 역할이라고 이해하면 된다.

**쉽게 정리하면:** 세션 계층은 "우리 지금 대화하고 있지? 이 대화를 어떻게 이어가고 끝낼까?"를 다룬다.

- 전송 단위(PDU): Data
- 보안 관련 개념: 세션 관리, 세션 탈취

단, 실제 네트워크에서는 세션 계층의 기능을 응용 프로그램 등이 담당할 수 있으며, TCP 연결과 로그인 세션은 서로 다른 개념이다.

## 3-4. 4계층 — 전송 계층(Transport Layer)

### "공이 올바른 친구에게 전달되도록 관리하자!"

이제 공 그림을 보내기 위한 준비가 끝났다고 생각해보자.

그런데 PC 2에는 여러 프로그램이 실행되어 있다.

브라우저도 있고, 게임도 있고, 메신저도 있다.

그렇다면 PC 1에서 보낸 데이터가 PC 2의 어떤 프로그램으로 가야 할까?

이때 중요한 것이 **Port 번호**다.

Port 번호는 데이터를 전달할 목적지 프로그램의 통신 지점을 구분하는 데 사용한다.

예를 들어 하나의 건물 안에 여러 사무실이 있다고 생각해보자.

IP 주소가 건물의 위치라면 Port 번호는 해당 건물에서 어느 사무실로 가야 하는지를 구분하는 번호와 비슷하다.

전송 계층에서는 대표적으로 TCP와 UDP를 사용한다.

**TCP(Transmission Control Protocol)**

TCP는 데이터가 순서대로 전달되도록 관리하고, 손실된 데이터를 재전송하는 등 신뢰성 있는 전송을 지원한다.

비유하면 공이 여러 조각의 데이터로 나뉘어 보내졌을 때, 필요한 조각이 빠지면 다시 보내달라고 요청하고 올바른 순서로 전달되도록 관리하는 역할이다.

**UDP(User Datagram Protocol)**

UDP는 TCP처럼 연결 설정이나 재전송을 자체적으로 제공하지 않는 단순한 전송 방식이다.

따라서 기본적인 처리 부담이 작으며, 실시간 통신이나 상위 프로토콜이 전송을 직접 관리하는 경우에 활용된다.

**쉽게 정리하면:** 전송 계층은 "어떤 프로그램에 데이터를 전달하고, 어떤 방식으로 전송할 것인가?"를 담당한다.

- TCP 전송 단위: Segment
- UDP 전송 단위: Datagram
- 보안 관련 사례: SYN Flood, 포트 스캔

## 3-5. 3계층 — 네트워크 계층(Network Layer)

### "공을 받을 친구의 집은 어디에 있을까?"

이번에는 공을 전달할 목적지의 주소가 필요하다.

택배를 보내려면 받는 사람의 집 주소가 필요한 것처럼, 네트워크에서도 목적지 주소가 필요하다.

이때 사용하는 것이 **IP 주소**다.

예를 들어 다음과 같은 환경을 생각해보자.

- PC 1: 192.168.0.10
- PC 2: 192.168.0.20

PC 1은 목적지 IP 주소를 이용해 데이터를 어디로 보낼지 결정한다.

만약 PC 2가 다른 네트워크에 있다면 중간에 라우터가 필요할 수 있다.

라우터는 목적지 IP 주소와 라우팅 테이블을 바탕으로 다음 전달 경로를 결정한다.

비유하면 택배가 여러 물류센터를 거쳐 목적지 지역으로 이동하는 것과 비슷하다.

**쉽게 정리하면:** 네트워크 계층은 "공을 어느 컴퓨터 주소로 보내고, 어떤 경로로 이동시킬까?"를 담당한다.

- 전송 단위(PDU): Packet
- 대표 프로토콜: IPv4, IPv6
- 주요 장비: Router
- 보안 관련 사례: IP Spoofing, 라우팅 공격

## 3-6. 2계층 — 데이터 링크 계층(Data Link Layer)

### "지금 이 구간에서 누구에게 공을 전달해야 할까?"

3계층에서 목적지의 IP 주소를 확인했다.

그런데 같은 네트워크 구간에서 실제로 어느 장치에 전달해야 하는지도 알아야 한다.

여기서 등장하는 것이 **MAC 주소**다.

MAC 주소는 네트워크 인터페이스를 식별하는 데 사용되는 주소다.

쉽게 비유하면 IP 주소가 목적지 집 주소라면, MAC 주소는 현재 전달 구간에서 상대 장치를 구별하는 이름표와 비슷하다.

이때 PC 1이 PC 2의 IP 주소는 알고 있지만 MAC 주소는 모른다면 어떻게 할까?

IPv4의 같은 LAN 환경에서는 **ARP(Address Resolution Protocol)**를 사용할 수 있다.

예를 들어 PC 1이 다음과 같이 질문하는 것이다.

"192.168.0.20이라는 IP 주소를 사용하는 장치는 누구야?"

그러면 해당 IP를 사용하는 PC 2가 자신의 MAC 주소를 응답할 수 있다.

PC 1은 이 정보를 이용해 목적지 MAC 주소 등이 포함된 Ethernet Frame을 만든다.

같은 LAN에서 스위치는 목적지 MAC 주소를 확인해 적절한 포트로 Frame을 전달할 수 있다.

**쉽게 정리하면:** 데이터 링크 계층은 "현재 네트워크 구간에서 공을 어느 장치에 전달할까?"를 담당한다.

- 전송 단위(PDU): Frame
- 대표 기술: Ethernet
- 주요 장비: Switch
- 보안 관련 사례: ARP Spoofing, MAC Flooding

여기서 주의할 점이 있다.

PC 2가 다른 네트워크에 있다면 PC 1은 일반적으로 PC 2의 MAC 주소가 아니라 **다음 경로인 기본 게이트웨이의 MAC 주소**를 이용한다.

즉 MAC 주소는 네트워크를 지날 때마다 달라질 수 있다.

## 3-7. 1계층 — 물리 계층(Physical Layer)

### "이제 공 정보를 실제 신호로 보내자!"

드디어 마지막 단계다.

지금까지 PC 1은 데이터를 전송하기 위해 필요한 여러 정보를 준비했다.

하지만 데이터를 실제로 전달하려면 물리적인 신호가 필요하다.

컴퓨터가 사용하는 데이터는 0과 1의 비트로 표현된다.

이 비트들은 전송 매체에 적합한 신호로 변환되어 이동한다.

예를 들어 다음과 같다.

- UTP 케이블: 전기 신호
- 광케이블: 빛
- 무선 네트워크: 전파

비유하면 지금까지 공을 보내기 위한 포장과 목적지 정보를 준비했다면, 물리 계층에서는 실제 운송이 이루어진다고 생각하면 된다.

다만 실제 축구공이 이동하는 것은 아니다.

축구공 그림을 나타내는 비트 정보가 신호 형태로 전달되는 것이다.

**쉽게 정리하면:** 물리 계층은 "데이터를 어떻게 실제 신호로 전달할까?"를 담당한다.

- 전송 단위(PDU): Bit
- 관련 요소: 케이블, 광섬유, 무선 신호, 물리 인터페이스
- 보안 관련 사례: 물리적 도청, 케이블 훼손

---

## 4. PC 2는 축구공 그림을 어떻게 받을까?

지금까지는 PC 1에서 데이터를 보내는 과정을 알아봤다.

PC 2에서는 반대 순서로 데이터를 처리한다.

1계층에서 물리 신호를 수신하고, 2계층에서 Frame을 처리한다.

이후 3계층에서 IP 정보를 확인하고, 4계층에서 데이터를 목적지 프로그램에 전달한다.

상위 계층에서는 필요한 대화 상태와 데이터 형식을 처리한 후 최종적으로 프로그램이 데이터를 사용한다.

결과적으로 PC 2 화면에 축구공 그림이 나타나게 된다.

여기서 중요한 개념이 **캡슐화(Encapsulation)**와 **역캡슐화(Decapsulation)**다.

송신 측에서는 데이터를 보내기 위해 필요한 정보를 계층별로 추가한다.

```text
응용 데이터
     ↓
TCP 헤더 + Data
     ↓
IP 헤더 + TCP Segment
     ↓
Ethernet 헤더 + IP Packet + FCS
     ↓
Bits
     ↓
물리 신호 전송
```

이러한 과정을 캡슐화라고 한다.

반대로 PC 2에서는 수신한 데이터를 계층별로 확인하고 필요한 제어 정보를 제거하여 상위 계층으로 전달한다.

이것을 역캡슐화라고 한다.

---

## 5. MAC 주소, IP 주소, Port 번호 차이

앞서 등장한 세 가지 주소 개념은 서로 다른 목적을 가지고 있다.

| 구분 | 역할 | 비유 |
|---|---|---|
| MAC 주소 | 현재 링크에서 네트워크 인터페이스 식별 | 장치의 이름표 |
| IP 주소 | 목적지 주소 및 네트워크 간 전달 | 집 주소 |
| Port 번호 | 통신할 프로그램 구분 | 건물 안의 사무실 번호 |

이 세 가지를 구분하면 네트워크 통신 과정이 훨씬 이해하기 쉬워진다.

예를 들어 PC 1이 PC 2의 특정 프로그램에 데이터를 전송한다고 생각해보자.

IP 주소는 어느 컴퓨터로 이동할지를 판단하는 데 사용되고, Port 번호는 해당 컴퓨터의 어느 프로그램에 전달할지 구분하는 데 사용된다.

MAC 주소는 현재 네트워크 구간에서 Frame을 전달할 장치를 구별하는 데 활용된다.

---

## 6. OSI 7계층과 TCP/IP 모델의 차이

OSI 7계층은 네트워크 통신을 개념적으로 이해하기 위한 참조 모델이다.

반면 오늘날 인터넷에서는 TCP/IP 프로토콜 구조가 주로 사용된다.

| OSI 7계층 | TCP/IP 4계층 |
|---|---|
| 7. 응용 | 응용 |
| 6. 표현 | 응용 |
| 5. 세션 | 응용 |
| 4. 전송 | 전송 |
| 3. 네트워크 | 인터넷 |
| 2. 데이터 링크 | 링크 |
| 1. 물리 | 링크 |

TCP/IP 모델에서는 OSI의 세션·표현·응용 계층에 해당하는 기능들이 주로 응용 계층에 포함된다.

따라서 실제 통신이 반드시 OSI의 7개 독립적인 프로토콜을 차례대로 사용한다는 의미는 아니다.

OSI 7계층은 통신 기능을 구분하고 문제를 이해하기 위한 지도라고 생각하면 좋다.

---

## 7. OSI 7계층과 정보보안

OSI 7계층은 정보보안을 공부할 때도 매우 중요하다.

그 이유는 네트워크 공격이 여러 계층의 기능을 악용해 발생할 수 있기 때문이다.

대표적인 공격 유형은 다음과 같다.

| 계층 | 보안 위협 예시 |
|---|---|
| 1계층 | 케이블 훼손, 물리적 도청 |
| 2계층 | ARP Spoofing, MAC Flooding |
| 3계층 | IP Spoofing, 라우팅 공격 |
| 4계층 | SYN Flood, 포트 스캔 |
| 5계층 관련 기능 | 세션 탈취 |
| 6계층 관련 기능 | 암호화·TLS 설정 오류 |
| 7계층 | SQL Injection, 악성 HTTP 요청 |

예를 들어 ARP Spoofing은 공격자가 거짓된 IP-MAC 주소 대응 정보를 전달하여 통신 경로를 악용하는 공격이다.

SYN Flood는 TCP의 연결 설정 과정을 악용해 서버 자원을 소모시키는 공격이다.

SQL Injection은 애플리케이션에서 입력값을 안전하게 처리하지 못하는 문제를 악용하는 공격이다.

이처럼 공격이 어떤 통신 기능과 관련되는지 이해하면 보안 문제를 분석할 때 도움이 된다.

다만 실제 공격은 여러 계층에 걸쳐 영향을 줄 수 있으므로, 모든 공격을 하나의 계층으로만 구분할 수 있는 것은 아니다.

---

## 8. AWS 클라우드 보안과 OSI 7계층

OSI 7계층을 이해하면 AWS의 네트워크 보안 서비스를 공부할 때도 도움이 된다.

### 8-1. AWS Security Group

Security Group은 EC2와 같은 리소스의 네트워크 접근을 제어하는 기능이다.

IP 주소, 프로토콜, Port 번호 등을 기준으로 트래픽을 허용한다.

Security Group은 **Stateful(상태 저장)** 방식으로 동작한다.

즉 허용된 통신의 응답 트래픽은 연결 상태를 고려해 처리된다.

### 8-2. Network ACL

Network ACL은 VPC의 서브넷 경계에서 트래픽을 제어하는 기능이다.

Security Group과 달리 **Stateless(상태 비저장)** 방식으로 동작한다.

따라서 인바운드와 아웃바운드 규칙을 각각 고려해야 한다.

### 8-3. AWS WAF

AWS WAF는 웹 애플리케이션에 전달되는 HTTP(S) 요청을 검사하고 필터링하는 서비스다.

주로 응용 계층인 7계층의 보안과 연결된다.

악성 요청이나 특정 공격 패턴을 탐지하고 차단하는 데 활용할 수 있다.

### 8-4. VPC Flow Logs

VPC Flow Logs는 네트워크 인터페이스 등을 통과하는 IP 트래픽의 흐름 정보를 기록하는 기능이다.

출발지와 목적지 IP, Port 번호, 프로토콜, 트래픽 허용 여부 등을 분석하는 데 도움을 준다.

단, 전체 패킷 내용을 저장하는 패킷 캡처 기능은 아니다.

이러한 기능들을 공부하면서 중요한 것은 단순히 AWS 서비스의 이름을 외우는 것이 아니라 **각 서비스가 네트워크의 어떤 정보를 바탕으로 보안을 제공하는지 이해하는 것**이다.

---

## 9. 실전 예시 — 웹사이트 접속이 안 된다면?

OSI 7계층을 이해하면 네트워크 장애를 분석할 때도 도움이 된다.

예를 들어 사용자가 웹사이트에 접속할 수 없다고 가정해보자.

이때 무작정 서버를 재시작하기보다는 문제의 범위를 단계적으로 좁히는 것이 좋다.

먼저 네트워크 연결 자체가 정상인지 확인한다.

그다음 DNS를 통해 도메인 이름이 올바른 IP 주소로 해석되는지 확인한다.

IP 연결과 라우팅 경로가 정상인지 확인하고, Security Group이나 Network ACL이 트래픽을 차단하고 있지는 않은지 살펴본다.

연결은 가능하지만 웹페이지가 표시되지 않는다면 TCP 연결, TLS 설정, HTTP 응답, 애플리케이션 상태 등을 추가로 점검할 수 있다.

이처럼 OSI 모델을 이해하면 막연한 네트워크 장애를 구체적인 점검 항목으로 나눌 수 있다.

## 10. 이번 학습을 통해 느낀 점

처음 OSI 7계층을 접했을 때는 일곱 개의 계층 이름과 프로토콜을 암기하는 것이 가장 중요한 부분이라고 생각하기 쉽다.

하지만 이번 내용을 정리하면서 더 중요한 것은 **데이터가 실제로 이동하는 과정과 각 계층의 역할을 연결해서 이해하는 것**이라는 점을 알게 되었다.

특히 MAC 주소, IP 주소, Port 번호는 모두 데이터를 전달하는 데 사용되지만 서로 다른 역할을 담당한다는 점이 인상적이었다.

또한 TCP와 UDP의 차이, 캡슐화와 역캡슐화, 스위치와 라우터의 역할도 서로 연결되는 개념이라는 것을 이해할 수 있었다.

클라우드 보안 측면에서도 이러한 네트워크 기초 지식이 중요하다는 것을 느꼈다.

예를 들어 AWS Security Group의 규칙을 설정할 때 IP와 Port 개념을 이해하고 있어야 하며, AWS WAF를 이해하려면 HTTP와 응용 계층에 대한 지식이 필요하다.

앞으로 클라우드 보안을 공부할 때도 단순히 서비스를 사용하는 방법만 배우는 것이 아니라,

**"이 서비스는 네트워크의 어떤 부분에서 동작하고, 어떤 보안 문제를 해결하는가?"**

라는 질문을 함께 생각하면서 공부하려고 한다.

---

## 마무리

이번 학습 내용을 세 문장으로 정리하면 다음과 같다.

1. **OSI 7계층**은 네트워크 통신 과정을 일곱 개의 역할로 나누어 설명하는 참조 모델이다.
2. 각 계층은 고유한 기능과 전송 단위(PDU)를 가지며, 송신 측에서는 캡슐화하고 수신 측에서는 역캡슐화하는 과정을 통해 데이터를 전달한다.
3. OSI 7계층의 이해는 네트워크 장애 분석과 보안 위협 파악뿐만 아니라 AWS와 같은 클라우드 환경의 보안 기술을 이해하는 데 중요한 기초가 된다.

결국 **OSI 7계층은 단순히 암기해야 하는 표가 아니라, 데이터가 어떻게 이동하고 어디에서 문제가 발생하는지 이해하기 위한 지도**라고 생각한다.
