## 들어가며

지난 시간에는 OSI 7계층과 TCP·UDP의 동작 원리를 공부했다.

이번에는 각 계층에서 사용되는 **네트워크 장비의 특징과 차이점**에 대해 알아보려고 한다.

네트워크에는 허브, 스위치, 라우터, 로드밸런서 등 다양한 장비가 존재한다.

이 장비들은 모두 데이터를 전달하는 데 관여하지만, 데이터를 처리하는 방식과 판단 기준이 서로 다르다.

이번 학습에서 가장 중요하게 생각한 질문은 다음과 같다.

> **"네트워크 장비는 무엇을 기준으로 데이터를 전달할까?"**

이 질문을 중심으로 OSI 1계층부터 4계층까지의 대표적인 장비를 정리해보겠다.

---

## 1. OSI 계층별 네트워크 장비

OSI 7계층은 네트워크 통신 과정을 일곱 개의 계층으로 나누어 설명하는 참조 모델이다.

각 계층은 서로 다른 역할을 담당하며, 장비도 주로 사용하는 정보에 따라 구분할 수 있다.

| 계층 | 대표 장비 및 요소 | 주요 판단 정보 | 데이터 단위 |
|---|---|---|---|
| 1계층 물리 | 리피터, 허브, 케이블 | 전기·빛 등의 신호 | Bit |
| 2계층 데이터 링크 | 브리지, 스위치 | MAC 주소 | Frame |
| 3계층 네트워크 | 라우터, L3 스위치 | IP 주소 | Packet |
| 4계층 전송 | L4 로드밸런서 | IP, Port, TCP/UDP | Segment / Datagram |

쉽게 비유하면 다음과 같다.

- 1계층: 데이터를 이동시키는 도로와 신호 전달
- 2계층: 같은 건물이나 구역에서 목적지 찾기
- 3계층: 다른 지역까지 이동할 경로 찾기
- 4계층: 여러 배송센터에 작업을 분산하기

물론 실제 네트워크 장비는 여러 계층의 기능을 함께 제공할 수 있다.

따라서 장비를 구분할 때는 단순히 몇 계층 장비인지 외우기보다 **어떤 정보를 기준으로 동작하는지**를 이해하는 것이 중요하다.

# 2. 1계층 — 물리 계층(Physical Layer)

물리 계층은 데이터를 실제 신호 형태로 전달하는 계층이다.

컴퓨터에서 사용하는 데이터는 0과 1로 표현되며, 이러한 비트는 전송 매체에 적합한 전기 신호, 빛 또는 전파 형태로 전달된다.

1계층에서 대표적으로 알아볼 요소는 리피터, 허브, 케이블이다.

## 2-1. 리피터(Repeater)

**리피터는 약해지거나 왜곡된 신호를 다시 재생하여 전달하는 장비다.**

예를 들어 넓은 운동장에서 멀리 떨어진 친구에게 소리를 전달한다고 생각해보자.

거리가 멀어질수록 소리를 정확하게 듣기 어려워진다.

이때 중간에 있는 사람이 소리를 다시 전달한다면 더 먼 곳까지 내용을 전할 수 있다.

리피터도 비슷한 역할을 한다.

네트워크 신호는 전송 과정에서 감쇠되거나 왜곡될 수 있는데, 리피터는 이를 다시 재생하여 다음 구간으로 전달한다.

중요한 점은 **리피터가 MAC 주소나 IP 주소를 확인하지 않는다는 것**이다.

리피터는 데이터의 목적지를 판단하는 것이 아니라 물리적인 신호를 다룬다.

### 리피터의 특징

- OSI 1계층에서 동작
- 약해진 신호를 재생하여 전달
- MAC 주소와 IP 주소를 기반으로 전달 경로를 결정하지 않음
- 물리적인 전송 구간을 확장하는 데 활용

## 2-2. 허브(Hub)

허브는 여러 장치를 연결할 수 있는 1계층 장비다.

리피터의 기능을 여러 포트로 확장한 장비라고 이해하면 쉽다.

예를 들어 PC A, B, C가 하나의 허브에 연결되어 있다고 가정해보자.

PC A가 PC B에게 데이터를 보내면 어떻게 될까?

```text
       PC A
         |
        HUB
       /   \
     PC B  PC C
```

허브는 PC B가 목적지인지 판단하지 않는다.

한 포트로 들어온 신호를 다른 포트들로 반복 전달한다.

따라서 PC B에게 보내려던 신호가 PC C 쪽으로도 전달된다.

전통적인 반이중 Ethernet 허브에서는 여러 장치가 동일한 충돌 도메인을 공유하기 때문에 동시에 전송하면 충돌이 발생할 수 있다.

이러한 비효율 때문에 오늘날의 일반적인 유선 LAN에서는 스위치가 허브를 대부분 대체했다.

### 허브의 특징

- 여러 장치를 하나의 네트워크 구간에 연결
- 목적지 MAC 주소를 확인하지 않음
- 들어온 신호를 다른 포트들에 반복 전달
- 전통적인 Ethernet 허브에서는 대역폭 및 충돌 도메인을 공유

## 2-3. 케이블(Cable)

케이블은 리피터나 허브처럼 신호를 능동적으로 처리하는 장비가 아니라, 신호가 이동하는 **물리적인 전송 매체**다.

대표적인 케이블은 다음과 같다.

| 종류 | 전송 방식 | 주요 특징 |
|---|---|---|
| UTP 케이블 | 전기 신호 | 일반적인 유선 LAN에 널리 사용 |
| 광섬유 케이블 | 빛 | 장거리·고대역폭 통신에 적합 |
| 동축 케이블 | 전기 신호 | 차폐 구조, 특정 통신 환경에서 사용 |

**UTP 케이블**은 일반적인 사무실이나 가정의 유선 LAN에서 자주 사용한다.

**광섬유 케이블**은 빛을 이용하기 때문에 전자기 간섭의 영향을 받지 않으며, 장거리와 고속 통신에 유리하다.

**동축 케이블**은 차폐 구조를 갖추고 있으며 방송이나 일부 통신 설비 등에서 사용된다.

케이블을 선택할 때는 단순히 빠른 제품을 고르는 것이 아니라 거리, 속도, 주변 환경, 비용 등을 함께 고려해야 한다.

# 3. 2계층 — 데이터 링크 계층(Data Link Layer)

1계층이 신호 자체를 전달하는 역할이라면, 2계층은 **현재 네트워크 구간에서 어떤 장치로 데이터를 전달할지 판단하는 역할**을 한다.

대표적인 장비는 브리지와 스위치다.

## 3-1. 브리지(Bridge)

브리지는 서로 다른 LAN 구간을 연결하면서 불필요한 데이터 전달을 줄이는 장비다.

쉽게 생각하면 두 교실 사이에 있는 안내 담당자와 비슷하다.

1반 학생에게 전달할 물건이라면 2반으로 보낼 필요가 없다.

브리지도 마찬가지다.

프레임의 MAC 주소 정보를 확인하여 다른 네트워크 구간으로 전달할 필요가 있는지 판단한다.

브리지는 수신한 프레임의 출발지 MAC 주소를 학습하고, 목적지 MAC 주소를 바탕으로 전달하거나 필터링한다.

이러한 기능을 통해 LAN 구간 사이의 불필요한 통신을 줄일 수 있다.

### 브리지의 특징

- OSI 2계층에서 동작
- MAC 주소를 기반으로 Frame 전달
- LAN 구간을 연결하고 트래픽을 필터링
- 전통적인 장비는 비교적 적은 수의 포트를 사용

## 3-2. 스위치(Switch)

스위치는 여러 네트워크 장치를 연결하고, MAC 주소를 기반으로 프레임을 전달하는 장비다.

허브와 가장 큰 차이는 **목적지를 판단할 수 있다는 것**이다.

예를 들어 네 대의 PC가 하나의 스위치에 연결되어 있다고 가정해보자.

```text
       PC A
         |
PC B -- SW -- PC C
         |
       PC D
```

PC A가 PC D에게 데이터를 전송한다.

허브라면 다른 모든 포트로 신호를 전달하지만, 스위치는 PC D의 MAC 주소가 어느 포트에 연결되어 있는지 알고 있다면 해당 포트로 프레임을 전달할 수 있다.

따라서 불필요한 트래픽을 줄이고 네트워크 효율을 높일 수 있다.

### MAC 주소 테이블이란?

스위치는 MAC 주소와 포트의 관계를 저장하는 MAC 주소 테이블을 사용한다.

예를 들어 다음과 같다.

| MAC 주소 | 연결 포트 |
|---|---|
| AA:AA | Port 1 |
| BB:BB | Port 2 |
| CC:CC | Port 3 |

스위치는 들어온 프레임의 **출발지 MAC 주소**를 확인하면서 어느 MAC 주소가 어떤 포트에 연결되어 있는지 학습한다.

반면 목적지 MAC 주소를 아직 모르는 경우에는 같은 VLAN의 다른 포트로 프레임을 플러딩할 수 있다.

이를 **Unknown Unicast Flooding**이라고 한다.

즉 스위치라고 해서 모든 프레임을 항상 특정 포트 하나에만 전달하는 것은 아니다.

## 3-3. 브리지와 스위치 비교

| 구분 | 브리지 | 스위치 |
|---|---|---|
| 동작 계층 | 2계층 | 주로 2계층 |
| 전달 기준 | MAC 주소 | MAC 주소 |
| 주요 목적 | LAN 구간 연결 및 필터링 | 여러 장치의 효율적인 연결 |
| 포트 수 | 전통적으로 소수 | 일반적으로 다수 |
| 처리 방식 | 전통적으로 소프트웨어 중심 사례 | 전용 하드웨어를 활용한 고속 처리 |
| 활용 | 브리징 개념 및 일부 네트워크 구성 | 현대 LAN의 핵심 장비 |

브리지와 스위치는 기본적인 동작 원리가 비슷하다.

따라서 **스위치는 여러 포트를 가진 고성능 브리지**라고 이해하면 쉽다.

# 4. 허브와 스위치의 차이점

허브와 스위치는 모두 여러 컴퓨터를 연결하지만 동작 방식이 다르다.

허브는 목적지를 판단하지 않고 신호를 반복 전달한다.

반면 스위치는 MAC 주소 테이블을 이용해 목적지 포트를 결정한다.

| 비교 | 허브 | 스위치 |
|---|---|---|
| 동작 계층 | 1계층 | 2계층 |
| 전달 기준 | 신호 | MAC 주소 |
| 목적지 구분 | 불가능 | 가능 |
| 트래픽 전달 | 다른 포트들로 반복 | MAC 학습 정보에 따라 전달 |
| 충돌 도메인 | 공유 | 포트별 분리 |
| 현대 LAN 활용 | 제한적 | 일반적으로 사용 |

특히 현대 스위치에서는 각 단말이 독립된 전이중(Full-Duplex) 링크를 이용할 수 있다.

전이중 통신은 양방향 데이터 전송을 동시에 수행할 수 있는 방식이다.

이러한 구조는 허브를 사용하는 전통적인 공유 Ethernet에 비해 효율적이다.

# 5. VLAN과 STP

스위치를 공부할 때 함께 알아두면 좋은 기술이 VLAN과 STP다.

## 5-1. VLAN(Virtual LAN)

VLAN은 하나의 물리적인 스위치 네트워크를 여러 개의 논리적인 네트워크로 구분하는 기술이다.

예를 들어 하나의 사무실에 개발팀과 인사팀이 있다고 가정해보자.

같은 스위치를 사용하더라도 다음처럼 VLAN을 구분할 수 있다.

```text
하나의 스위치
     |
     |--- VLAN 10 : 개발팀
     |
     |--- VLAN 20 : 인사팀
```

VLAN을 사용하면 서로 다른 VLAN의 브로드캐스트 도메인을 분리할 수 있다.

서로 다른 VLAN 사이에서 통신하려면 라우터나 L3 스위치 같은 3계층 기능이 필요하다.

보안 측면에서도 네트워크를 구분하는 데 도움이 되지만, VLAN 설정 자체가 완전한 접근 통제나 방화벽을 대신하는 것은 아니다.

## 5-2. STP(Spanning Tree Protocol)

STP는 스위치 네트워크에서 발생할 수 있는 루프를 방지하는 기술이다.

쉽게 생각하면 자동차가 같은 도로를 계속 순환하는 상황과 비슷하다.

스위치 사이에 중복 경로가 존재할 때, 잘못 구성된 네트워크에서는 프레임이 계속 순환하는 문제가 발생할 수 있다.

STP는 중복 경로 중 일부를 논리적으로 차단하여 이러한 루프를 방지한다.

# 6. 3계층 — 네트워크 계층(Network Layer)

3계층의 대표적인 장비는 **라우터(Router)**다.

2계층 스위치가 같은 LAN 내에서 MAC 주소를 기준으로 데이터를 전달한다면, 라우터는 IP 주소를 이용해 서로 다른 네트워크 사이에서 패킷을 전달한다.

## 6-1. 라우팅(Routing)이란?

라우팅은 목적지 네트워크까지 패킷을 전달하기 위해 다음 경로를 결정하는 과정이다.

택배 배송에 비유하면 이해하기 쉽다.

택배를 다른 지역으로 보내려면 목적지 주소를 확인하고 어느 물류센터를 거쳐야 할지 판단해야 한다.

라우터도 이와 비슷하다.

```text
PC A
192.168.1.10
     |
  Router 1
     |
  Router 2
     |
PC B
10.0.2.20
```

PC A가 다른 네트워크에 있는 PC B로 데이터를 보내려고 한다.

라우터는 패킷의 목적지 IP 주소를 확인하고, 라우팅 테이블을 참고해 다음 경로를 선택한다.

이렇게 각 라우터가 다음 전달 지점을 결정하며 패킷이 목적지까지 이동한다.

## 6-2. 라우팅 테이블(Routing Table)

라우팅 테이블은 라우터가 패킷을 전달할 경로 정보를 저장하는 표다.

예를 들어 다음과 같은 정보가 있다고 가정해보자.

| 목적지 네트워크 | 다음 경로 |
|---|---|
| 10.0.0.0/8 | Router A |
| 10.1.0.0/16 | Router B |
| 0.0.0.0/0 | 기본 경로 |

목적지 IP가 `10.1.2.3`이라면 어느 경로를 선택해야 할까?

10.0.0.0/8과 10.1.0.0/16 모두 목적지 주소와 일치한다.

이때는 더 구체적인 경로인 **10.1.0.0/16**이 선택된다.

이를 **Longest Prefix Match(최장 프리픽스 일치)**라고 한다.

`0.0.0.0/0`은 기본 경로(Default Route)를 의미하며, 더 구체적으로 일치하는 경로가 없을 때 사용할 수 있다.

---

# 7. 정적 라우팅(Static Routing)

정적 라우팅은 관리자가 라우터에 목적지 네트워크와 다음 경로를 직접 설정하는 방식이다.

쉽게 비유하면 자동차 내비게이션에서 이동 경로를 사람이 직접 지정하는 것과 비슷하다.

예를 들어 특정 네트워크로 가는 패킷은 항상 지정된 라우터로 보내도록 설정할 수 있다.

### 정적 라우팅의 장점

- 설정이 비교적 단순함
- 경로를 예측하고 관리하기 쉬움
- 별도의 동적 라우팅 프로토콜 운영이 필요하지 않음
- 네트워크 구조가 단순한 환경에 적합

### 정적 라우팅의 단점

- 네트워크 구조가 커지면 관리 부담 증가
- 회선 장애나 경로 변화에 자동으로 대응하기 어려움
- 경로 변경 시 관리자의 설정 작업이 필요할 수 있음

단, 보조 정적 경로나 경로 추적 기능을 함께 구성하면 일부 장애 상황에 대응할 수 있다.

---

# 8. 동적 라우팅(Dynamic Routing)

동적 라우팅은 라우터들이 라우팅 프로토콜을 이용해 경로 정보를 교환하는 방식이다.

쉽게 말하면 도로 상황을 공유하는 내비게이션과 비슷하다.

어떤 도로에 장애가 발생하면 다른 경로 정보를 바탕으로 새로운 길을 선택할 수 있다.

대표적인 라우팅 프로토콜은 다음과 같다.

| 프로토콜 | 특징 |
|---|---|
| RIP | 홉 수 기반의 거리 벡터 라우팅 |
| OSPF | 링크 상태 정보를 활용하는 내부 라우팅 프로토콜 |
| BGP | 인터넷과 같은 대규모 네트워크에서 경로 및 정책 정보를 교환 |

### 동적 라우팅의 장점

- 네트워크 변화에 대응 가능
- 라우터 간 경로 정보 교환
- 규모가 큰 네트워크에 유리
- 경로 변경에 따른 수동 작업 감소

### 동적 라우팅의 단점

- 설정과 관리가 상대적으로 복잡함
- 프로토콜에 대한 이해가 필요함
- 경로 변경 시 수렴 시간이 발생할 수 있음
- 잘못된 설정이 다른 라우터에 영향을 줄 수 있음

동적 라우팅이라고 해서 장애 발생 즉시 새로운 경로로 전환되는 것은 아니다.

장애를 감지하고 새로운 경로를 계산하거나 선택하는 과정이 필요하다.

## 8-1. 정적 라우팅과 동적 라우팅 비교

| 구분 | 정적 라우팅 | 동적 라우팅 |
|---|---|---|
| 경로 설정 | 관리자 직접 설정 | 프로토콜을 이용한 경로 학습 |
| 구조 | 비교적 단순 | 상대적으로 복잡 |
| 장애 대응 | 기본적으로 수동 관리 필요 | 경로 재선택 가능 |
| 운영 부담 | 경로 증가 시 관리 부담 증가 | 초기 설계 및 프로토콜 관리 필요 |
| 적합한 환경 | 소규모·단순 네트워크 | 중대형·복잡한 네트워크 |

실제 네트워크에서는 정적 라우팅과 동적 라우팅을 함께 사용하기도 한다.

예를 들어 기본 경로는 정적으로 설정하고, 내부 네트워크에서는 OSPF를 활용할 수 있다.

---

# 9. 4계층 — 전송 계층(Transport Layer)

4계층에서는 TCP와 UDP의 동작 특성을 활용하여 트래픽을 처리하는 장비를 알아볼 수 있다.

대표적인 예시가 **L4 로드밸런서(Load Balancer)**다.

## 9-1. 로드밸런싱(Load Balancing)이란?

로드밸런싱은 들어오는 네트워크 트래픽이나 작업을 여러 서버에 분산하는 기술이다.

예를 들어 쇼핑몰 웹사이트를 운영한다고 가정해보자.

처음에는 서버 한 대로 서비스를 운영할 수 있다.

하지만 사용자가 갑자기 늘어나면 문제가 발생할 수 있다.

서버 한 대에 모든 요청이 집중되면 응답 속도가 느려지거나 서비스 장애가 발생할 수 있기 때문이다.

이때 여러 서버를 사용하고 요청을 분산하면 부하를 나눌 수 있다.

```text
            사용자
               |
         Load Balancer
          /    |    \
         /     |     \
     Server A Server B Server C
```

로드밸런서는 여러 서버의 상태와 분산 정책을 바탕으로 트래픽을 전달한다.

또한 헬스 체크(Health Check)를 통해 서버의 상태를 확인하고, 비정상적인 서버를 신규 트래픽의 대상에서 제외할 수 있다.

다만 로드밸런서를 사용한다고 모든 장애가 자동으로 해결되는 것은 아니다.

가용 영역 분산, 서버 상태, 네트워크 구성 등을 함께 고려해야 한다.

---

# 10. 대표적인 로드밸런싱 알고리즘

로드밸런싱에서는 서버를 선택하는 방식도 중요하다.

대표적인 알고리즘은 다음과 같다.

## 10-1. Round Robin(라운드 로빈)

라운드 로빈은 서버를 순서대로 돌아가며 선택하는 방식이다.

예를 들어 다음과 같다.

```text
요청 1 → Server A
요청 2 → Server B
요청 3 → Server C
요청 4 → Server A
요청 5 → Server B
```

구조가 단순하고 구현하기 쉽다는 장점이 있다.

하지만 각 서버의 현재 부하나 요청 처리 시간이 다를 경우 효율이 떨어질 수 있다.

## 10-2. Least Connections(최소 연결)

최소 연결 방식은 현재 활성 연결 수가 가장 적은 서버를 우선 선택하는 방식이다.

예를 들어 서버별 연결 수가 다음과 같다고 가정해보자.

| 서버 | 활성 연결 수 |
|---|---|
| Server A | 30 |
| Server B | 10 |
| Server C | 20 |

이 경우 Server B가 새로운 연결의 우선 대상이 될 수 있다.

라운드 로빈과 달리 서버의 연결 상태를 고려한다는 특징이 있다.

다만 연결 수가 실제 CPU 사용률이나 요청 처리 비용을 완벽하게 나타내는 것은 아니다.

## 10-3. Hash 기반 분산

해시 기반 분산은 출발지와 목적지의 IP 주소, Port 번호, 프로토콜 등 특정 정보를 계산에 활용하여 대상 서버를 선택하는 방식이다.

같은 흐름의 트래픽을 동일한 서버로 전달해야 하는 환경에서 유용하다.

특히 AWS Network Load Balancer는 흐름 해시 방식으로 대상을 선택한다.

따라서 **AWS NLB가 단순한 라운드 로빈 방식으로 서버를 선택한다고 이해하면 안 된다.**

# 11. AWS NLB와 ALB의 차이

로드밸런싱은 AWS 클라우드 환경에서도 매우 중요한 기술이다.

AWS에서는 대표적으로 Network Load Balancer와 Application Load Balancer를 사용할 수 있다.

## 11-1. Network Load Balancer(NLB)

NLB는 주로 OSI 4계층에서 동작하는 로드밸런서다.

TCP, UDP 등 전송 계층의 트래픽을 처리하며, IP 주소와 Port 번호 같은 흐름 정보를 활용한다.

NLB는 흐름 해시 알고리즘으로 대상 서버를 선택한다.

TCP의 경우 IP 주소·Port·프로토콜 외에 TCP 시퀀스 번호도 대상 선택에 활용하며, UDP의 경우에는 일반적으로 5튜플 정보를 활용한다.

## 11-2. Application Load Balancer(ALB)

ALB는 OSI 7계층인 응용 계층에서 동작하는 로드밸런서다.

HTTP 요청의 Host나 URL 경로 등 애플리케이션 정보를 분석하여 요청을 전달할 서버 그룹을 결정할 수 있다.

예를 들어 다음과 같이 설정할 수 있다.

```text
example.com/images → 이미지 서비스
example.com/api    → API 서비스
example.com/shop   → 쇼핑 서비스
```

이처럼 ALB는 웹 애플리케이션의 요청 내용을 기준으로 세부적인 라우팅을 수행할 수 있다.

### NLB와 ALB 비교

| 구분 | NLB | ALB |
|---|---|---|
| 주요 계층 | 4계층 | 7계층 |
| 판단 기준 | 프로토콜·IP·Port·흐름 | HTTP Host·Path 등 |
| 주요 용도 | TCP/UDP 등 네트워크 트래픽 처리 | HTTP/HTTPS 웹 서비스 |
| 분산 방식 | 흐름 해시 기반 | 대상 그룹의 분산 알고리즘 |
| 대표 활용 | 네트워크 서비스 | 웹·API·마이크로서비스 |

AWS 환경에서도 서버의 목적과 사용하는 프로토콜에 따라 적합한 로드밸런서를 선택해야 한다.

# 12. 네트워크 장비와 클라우드 보안의 관계

이번에 공부한 장비들은 네트워크 통신뿐만 아니라 정보보안과도 밀접한 관련이 있다.

### 1계층 — 물리적 접근과 신호 보호

케이블과 물리적 네트워크 장비는 훼손되거나 무단으로 접근당할 수 있다.

따라서 물리적 접근 통제와 장비 관리가 중요하다.

### 2계층 — MAC 기반 통신과 네트워크 분리

스위치는 MAC 주소를 이용해 데이터를 전달한다.

이 과정에서 ARP Spoofing이나 MAC Flooding 같은 공격을 이해할 필요가 있다.

또한 VLAN을 활용하면 네트워크를 논리적으로 구분할 수 있다.

### 3계층 — IP 기반 경로와 접근 제어

라우터는 IP 주소를 기반으로 데이터를 전달한다.

잘못된 라우팅 설정은 통신 장애나 의도하지 않은 경로로의 전달 문제를 발생시킬 수 있다.

따라서 라우팅 테이블과 네트워크 경로를 이해하는 것이 중요하다.

### 4계층 — 서비스 가용성과 트래픽 관리

로드밸런서는 여러 서버에 트래픽을 분산하여 서비스 가용성을 높이는 데 도움을 준다.

하지만 분산만으로 모든 보안 위협을 차단할 수는 없다.

DDoS 방어, 접근 제어, 상태 모니터링 등은 별도로 함께 고려해야 한다.

**네트워크 장비의 역할을 이해하는 것은 보안 사고 발생 시 어느 부분에서 문제가 발생했는지 판단하는 데 중요한 기초가 된다.**

---

# 13. 이번 학습을 통해 느낀 점

이번에는 OSI 1계층부터 4계층까지 사용되는 네트워크 장비의 특징과 차이점을 공부했다.

처음에는 허브, 스위치, 라우터가 모두 데이터를 전달하는 장비이기 때문에 어떤 차이가 있는지 명확하게 구분하기 어려웠다.

하지만 각 장비가 **무엇을 기준으로 데이터를 전달하는지**를 중심으로 학습하니 차이를 이해하기 쉬웠다.

특히 허브와 스위치의 차이가 인상적이었다.

허브는 목적지를 판단하지 않고 신호를 반복 전달하지만, 스위치는 MAC 주소를 학습하여 필요한 포트로 프레임을 전달할 수 있다는 점에서 네트워크 효율이 달라진다는 것을 알게 되었다.

또한 라우팅을 공부하면서 IP 주소와 라우팅 테이블의 역할을 이해할 수 있었다.

정적 라우팅과 동적 라우팅도 단순히 수동과 자동이라는 차이뿐 아니라, 네트워크의 규모와 운영 환경에 따라 적합한 방식이 달라진다는 점을 알 수 있었다.

마지막으로 로드밸런싱을 공부하면서 네트워크 기초 개념이 AWS 클라우드 환경과 직접 연결된다는 사실을 확인할 수 있었다.

앞으로 AWS를 공부할 때도 단순히 서비스의 사용 방법을 외우는 것이 아니라,

**"이 서비스는 어떤 정보를 기준으로 동작하며, 어떤 네트워크 문제를 해결하기 위한 것인가?"**

라는 질문을 함께 생각하며 학습해야겠다고 느꼈다.

# 마무리 — 3줄 요약

1. **1계층 장비인 리피터와 허브는 물리적인 신호를 전달하고, 2계층 장비인 브리지와 스위치는 MAC 주소를 기준으로 프레임을 전달한다.**
2. **3계층 라우터는 IP 주소와 라우팅 테이블을 활용해 경로를 결정하며, 정적 라우팅과 동적 라우팅은 경로 설정 및 관리 방식에서 차이가 있다.**
3. **4계층 로드밸런서는 TCP·UDP 트래픽을 여러 서버에 분산하며, 이러한 네트워크 장비의 역할을 이해하는 것은 네트워크 장애 분석과 클라우드 보안 설계의 기초가 된다.**
